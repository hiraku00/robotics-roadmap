# ロボティクスエンジニア 6ヶ月ロードマップ（実機なし・日本語教材版）

[@DeRonin_「How to become a Robotics Engineer in 6 months」](https://x.com/DeRonin_/status/2095180126359105955)（以下「元記事」）の6ヶ月のカリキュラムを、**電子回路の知識ゼロ・実機を買う予算なし**の状態から進めるための学習記録です。

元記事の6ヶ月を6つの「フェーズ」に分け、各フェーズを週単位で進めます。フェーズ1〜2は日別のチェックリストまで作ってあり、フェーズ3〜6は週ごとの計画です。フェーズ3以降の日別チェックリストは、そのフェーズを始める前に日本語の教材を確認してから作ります。

- 分からない言葉：[用語集（GLOSSARY.md）](GLOSSARY.md)
- 教材の一覧と、URLをどこまで確認したか：[MATERIALS.md](MATERIALS.md)
- ROS 2の演習（フェーズ4の一部を先に進めている）：[hiraku00/ros2_ws](https://github.com/hiraku00/ros2_ws)

## このリポジトリの方針（元記事との違い）

| 項目 | 元記事 | このリポジトリ |
| --- | --- | --- |
| 実機 | Month 1からスターターキットとテスターを買う。予算別に4段階（$0〜$300） | 一番下の段階（$0）だけで進める。回路は Tinkercad・Falstad、マイコンは Tinkercad・Wokwi、ロボットは Python・Gazebo・MuJoCo のシミュレーションで代わりにする |
| 教材 | 英語の教材が中心 | 日本語の教材を優先し、日本語で見つからないものだけ英語にする |
| 時間 | 1日2〜3時間 | 1日約2時間、週6日（日曜は休み） |
| Python・ターミナル・Git | Month 1で学ぶ | ros2_ws などですでに使っているので、学習の時間は取らない。代わりに、このリポジトリで「毎回READMEと失敗の記録を書く」ことを練習にする |
| 実機でしかできないこと | 各月の課題に含まれる | 座学と設計までやり、「[実機を買ったらやり直すこと](#実機を買ったらやり直すこと)」に積んでおく |

## 元記事のカリキュラムと、このリポジトリでの対応

元記事の各月を「学ぶ内容」「課題（Practice task）」「到達目標（Milestone）」に分け、このリポジトリのどこで扱うかを書いています。状態の意味は次のとおりです。

| 状態 | 意味 |
| --- | --- |
| 対応 | 元記事とほぼ同じ内容をやる |
| 代替 | 実機の代わりにシミュレータや計算でやる。考え方は同じだが、本物の手応えは実機待ち |
| 一部 | 内容の一部だけやる。残りは補足に書いた |
| 実機待ち | 実機がないとできない。座学だけ先にやり、購入後にやり直す |
| 既習 | 別のところで経験済みなので、学習の時間は取らない |
| 予定 | まだ計画だけ。日別チェックリストはフェーズ開始前に作る |
| 追加 | 元記事にはないが、このリポジトリで足した |

## 進め方

1. 1日の目安は約2時間です。流れは「読む（20〜30分）→ シミュレータで手を動かす（60〜80分）→ 予想・結果・差の理由を記録（10〜15分）」。
2. 測定や実験は、**やる前に予想を書く**。各週の README にある「予想 → 結果 → 差の理由」の表に残す。
3. 週の終わりに、各週の README の「何が壊れてどう直したか」を必ず埋める。元記事が「1つだけ持ち帰るならこれ」と書いているのが、この記録です。
4. その日の項目が終わったら、そのフェーズの CHECKLIST.md の `- [ ]` を `- [x]` にしてコミットする。コミットメッセージは `day03: 直列回路` のように日番号から始める。
5. 詰まったら次の日に進まず、その日をやり直す。土曜日は遅れを取り戻す日でもある。
6. フェーズを始める前に、そのフェーズの日本語教材を探して確認し、CHECKLIST.md を作る（フェーズ3以降）。
7. 英語の教材は、ブラウザのページ翻訳で読む。回路図・コード・数式は翻訳の影響を受けません。
